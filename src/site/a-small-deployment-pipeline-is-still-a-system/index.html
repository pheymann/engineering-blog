A small deployment pipeline is still a system

September 4, 2026

A publishing path can be compact without being casual. Once a file can become a public page, the hand-off needs a shape that is easy to inspect when something changes.

Three boundaries are enough to start

For a static site, I want the input, generated output, and deployment command to remain separate. That makes it possible to check each boundary independently.

  1. Write content as plain, versioned files.
  2. Build a complete static directory from those files.
  3. Publish that directory as one reviewed release.

The useful question is not “is this sophisticated?” It is “can I tell what happened when it fails?”

Let the command say what it does

A small command can still make the sequence visible. The local-first approach keeps that command close to the writing.

npm run build
npx wrangler deploy

There is no need for a dashboard ritual or a background client1 in the reader’s browser. The published result is just files.

1 This is a mock note for the MVP. The actual publishing setup will be documented separately.
